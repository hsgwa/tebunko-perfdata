# tebunko-perfdata

[tebunko](https://github.com/hsgwa/tebunko) の性能テストに使う、大量の Excel ブックを作る道具。本体のリポジトリとは分けて置く。

ブックは git に入れない（全部で約 850MB になるため）。このリポジトリには、ブックを作るスクリプトだけを置く。

## できるもの

tebunko の検索の計測（`docs/02_検索.md` 4.4 の「合成データ: ブック 5.4 万・TSV 16 万・1GB」）に使ったインデックスと同じ形の Excel ブック。

| 項目 | 値 |
|---|---|
| ブック | 53,603 冊（`部署0`〜`部署51` / `年度0`〜`年度9` / `資料<番号>.xlsx`）と、大きいブック 1 冊（`大きい/乱数.xlsx`） |
| シート | 1 冊に 1〜5 枚（`シート1`〜`シート5`。枚数はほぼ均等）。合計 約 16 万枚 |
| 1 シートの中身 | 20〜320 行 × 5 列: 整数、漢字 0〜8 文字、漢字 0〜4 文字、桁区切りの数値（`346,965`）、`〜の〜` |
| 1 シートの大きさ | TSV にして中央値 約 5KB・最大 約 17KB |
| 大きいブック | 1 列 × 70,003 行（1 行 50 文字。TSV にして 10MB） |
| 文字 | 漢字（U+4E00〜U+5057）にカタカナを約 4% 混ぜた乱数 |
| 図形・コメント | 無い |
| 合計 | TSV にして約 1GB、xlsx で約 850MB |

文字はすべて乱数で、実在の人名・組織名は含まない。ブックには作成者名などの情報（`docProps`）を入れない。

## 作り方

必要なもの: Windows PowerShell 5.1。Excel は要らない（xlsx の中の XML を直接書く）。

作るのは 2 段階。

```powershell
# 1. 乱数から、tebunko のインデックスと同じ形の TSV を作る
.\tools\new_index.ps1 -Dest .\index

# 2. TSV から Excel ブックを作る
.\tools\new_books.ps1 -Source .\index -Dest .\books
```

1 の TSV は、そのまま tebunko のインデックスとしても使える（Excel から取り込む時間をかけずに検索だけを測るとき）。

| スクリプト | 主な指定 | 時間の目安（4 スレッド） |
|---|---|---|
| `new_index.ps1` | `-Seed`（乱数の種。既定 1）、`-Scale`（ブックの数の割合。`0.1` で 1 割）、`-Workers` | 1,072 冊で 29 秒（大きいブックの約 20 秒を含む） |
| `new_books.ps1` | `-Limit`（先頭から N 冊だけ）、`-Workers` | 53,604 冊で 25 分 |

- どちらも作成済みのものは飛ばすので、止めても続きから作れる。
- 同じ種・同じ `-Scale` からは、スレッドの数によらず同じ TSV ができる。zip の中の日時も固定しているので、同じ TSV からは同じ xlsx ができる。
- 計測に使った元のインデックスを持っていれば、1 を飛ばして、それを `new_books.ps1` の `-Source` に渡すと、計測と同じ中身のブックができる。

### 元の TSV と同じになるか

作ったブックを tebunko で取り込むと、元の TSV とバイト単位で同じ TSV ができる（計測に使ったインデックスの 20 冊・57 シート（大きいブックを含む）と、`new_index.ps1` で作った 15 冊・43 シートで確認）。そのために次のように書く。

| TSV の値 | ブックのセル |
|---|---|
| 整数（`88723`） | 数値 |
| 引用符で囲んだ桁区切りの数値（`"346,965"`） | 数値＋表示形式 `#,##0`。Excel はこの表示値を引用符で囲んで書き出す |
| 空 | 空のセル |
| それ以外 | 文字列。セル内改行（U+2028）はセルの中の改行に戻し、引用符で囲んだ値は外側の `"` を外して `""` を `"` に戻す |

先頭が 0 の数字や 16 桁以上の数字は、Excel の表示が変わるため文字列のままにする。

## 性能テストでの使い方

1. tebunko の［1 インデックス管理］で、`books` をクロール対象フォルダに追加して、インデックスを作る。
2. 検索の速さを測る。

ワークスペース（インデックスの置き場所）は、ふだん使っているものと分けておく。

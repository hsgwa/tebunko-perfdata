# tebunko-perfdata

[tebunko](https://github.com/hsgwa/tebunko) の性能テストに使う、大量の Excel ブックを作る道具。本体のリポジトリとは分けて置く。

ブックは git に入れない（数百 MB になるため）。このリポジトリには、ブックを作るスクリプトだけを置く。

## できるもの

tebunko の検索の計測（`docs/02_検索.md` 4.4 の「合成データ: ブック 5.4 万・TSV 16 万・1GB」）に使ったインデックスと同じ中身の Excel ブック。

| 項目 | 値 |
|---|---|
| ブック | 53,604 冊（`部署0`〜`部署51` / `年度0`〜`年度9` / `資料<番号>.xlsx`）と、大きいブック 1 冊（`大きい/乱数.xlsx`） |
| シート | 1 冊に 1〜5 枚（`シート1`〜`シート5`。枚数はほぼ均等）。合計 160,985 枚 |
| 1 シートの中身 | 5 列: 整数、ランダムな漢字、ランダムな漢字（空のこともある）、桁区切りの数値（`346,965`）、`〜の〜` |
| 1 シートの大きさ | TSV にして中央値 5.2KB・最大 17KB |
| 大きいブック | 1 列 × 70,003 行（TSV にして 10MB） |
| 図形・コメント | 無い |
| TSV にした合計 | 1,035MB |

文字はすべて乱数で作ったもので、実在の人名・組織名は含まない。ブックには作成者名などの情報（`docProps`）を入れない。

## 作り方

必要なもの: Windows PowerShell 5.1。Excel は要らない（xlsx の中の XML を直接書く）。

元にするのは、tebunko が作ったインデックス（場所ごとの TSV）。

```powershell
.\tools\new_books.ps1 -Source <index のフォルダ> -Dest .\books
```

- `<Source>\部署0\年度0\資料1.xlsx\シート1.tsv` が、`<Dest>\部署0\年度0\資料1.xlsx` の「シート1」になる。
- 作成済みのブックは飛ばすので、止めても続きから作れる。
- `-Limit 20` で先頭の 20 冊だけ作れる。`-Workers` で並行して作るスレッドの数を変えられる（既定 4）。
- zip の中の日時を固定しているので、同じ TSV からは同じ xlsx ができる。

### 元の TSV と同じになるか

作ったブックを tebunko で取り込むと、元の TSV とバイト単位で同じ TSV ができる（20 冊・57 シートで確認。大きいブックを含む）。そのために次のように書く。

| TSV の値 | ブックのセル |
|---|---|
| 整数（`88723`） | 数値 |
| 引用符で囲んだ桁区切りの数値（`"346,965"`） | 数値＋表示形式 `#,##0`。Excel はこの表示値を引用符で囲んで書き出す |
| 空 | 空のセル |
| それ以外 | 文字列。セル内改行（U+2028）はセルの中の改行に戻し、引用符で囲んだ値は外側の `"` を外して `""` を `"` に戻す |

先頭が 0 の数字や 16 桁以上の数字は、Excel の表示が変わるため文字列のままにする。

## 性能テストでの使い方

1. tebunko の［1 インデックス管理］で、`books` をクロール対象フォルダに追加して、インデックスを作る。
2. 検索の速さを測る。

ワークスペース（インデックスの置き場所）は、ふだん使っているものと分けておく。
